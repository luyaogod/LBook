# 05 —— 界面多语言（i18next）

**状态**：✅ 已完成（2026-10-11）。界面串由守门脚本 `npm run check:i18n` 锁住；注释与测试名已改英文。**翻译相关的厂商报错不做双语**（用户拍板，见 I6）。

## 已定

| # | 决定 | 依据 |
|---|---|---|
| I1 | **i18next + react-i18next**，词典是 TypeScript 模块（不是 JSON） | 用户拍板；TS 模块换来 `t()` 的 key 类型（`i18next.d.ts`），JSON 词典写错 key 只在运行时现形 |
| I2 | **英文是唯一真值来源**，`zh-CN.ts` 的类型是 `Record<TranslationKeys, string>` | 新增 key 不翻译就编译不过——半翻译的界面正是这么活到发版那天的 |
| I3 | **语言名自己叫自己**（English / 简体中文 / 跟随系统） | 一份"翻译成当前语言的语言列表"恰恰是读者读不懂的那份。语言名不进词典 |
| I4 | `locale: "system" \| "en" \| "zh-CN"` 存 `config.json`，默认 `"en"` | 默认英文（界面基准），"跟随系统"由渲染层的 `navigator.language` 解析，不需要 IPC |
| I5 | 设置里**立刻**有 Language 三张卡片 | 用户要"英文和简中都适配"，那就得能切 |
| **I6** | **翻译厂商的报错不做双语**（2026-10-11 用户拍板） | 那些消息本来就来自腾讯云（错误码 + RequestId，还带英文技术名词），把它们 code 化再翻译，收益是翻一句技术错误、代价是给主进程加一层 `{ code, params }` 协议与两处渲染层分支。**推论**：主进程只发英文句子，选简体中文时那几行仍是英文——已记在 `TEST.md` 第 6 节，免得被当成 bug |
