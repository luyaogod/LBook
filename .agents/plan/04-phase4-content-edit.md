# Phase 4 —— 按字段修正内容（编辑，独立立项）

**状态**：🟡 动工中（2026-10-11）。三条待拍板已定为 A18/A19/A20；T1 定位器与 T2 写路径先做，界面（T3/T4）随后。

**目标**：能在应用里**修正 OCR 的内容**——一个块的文字，或一页的 Markdown——并且**当场写进 `ocr.json`**，其余字节一个不动。

**与上一版（Monaco 按页编辑整页 JSON）的差别**：那一版把一页的 JSON 交给编辑器，等于把**坐标**（`block_bbox`）、结构、缩进全暴露成可编辑文本，还要 JSON Schema、diagnostics、worker。用户 2026-10-11 定的原则把它收窄了：

1. **坐标是 OCR 工具的产物，我们信任它，不改**。编辑器只写**两个字符串字段**：`parsing_res_list[i].block_content` 与 `markdown.text`。这不是"约定禁止改 bbox"，而是**没有那条代码路径**。
2. **只在翻页模式下编辑**。页是文件的单位（数组元素），编辑的原子性正好是它；连滚模式下改一页等于在读者眼前改他正在读的版面，而且"当前页"在那里是模糊的。连滚模式给一个"到翻页模式改这一页"的入口即可，不做第二套编辑界面。
3. **一次编辑 = 一个页元素里的一个字段**。块编辑 = 第 i 个块的 `block_content`；Markdown 编辑 = 这一页的 `markdown.text`（那是**一个**字段）。
4. **编辑的就是源码**（用户 2026-10-11 明确）：编辑器里出现的是文件里那段字符本身——Markdown 是 Markdown 源文，表格块是 HTML 源码。**不做所见即所得**，也不做"渲染后再转回源"（有损且让人误以为在改显示效果）。这不是将就，是要改的本来就是文件里的字节。

---

## 一次编辑要付多少代价（2026-10-11 实测，`npm run probe:edit`）

最慢的那本（BPP，`ocr.json` 7.9MB、665 页），改第 21 页第 1 个块（原值 59 字节，替换值 74 字节）：

| 步骤 | 耗时 |
|---|---|
| 定位字段（内存里在页切片中找） | 0.9 ms |
| 复制 `ocr.json` | 3.4 ms |
| 拼接新文件（内存） | 0.9 ms |
| 写入拼接结果 | 2.3 ms |
| rename 覆盖 | 0.9 ms |
| **合计** | **7.5–8.5 ms** |

并且实测：**前缀与后缀逐字节相同**（只有那 59 个字节被替换），文件长度正好 +15。

两个关键事实：

- **只写 `ocr.json`——最大 7.9MB。PNG 与 PDF（最大 190MB）永不被编辑触碰**，所以"编辑=重写整个文件"这件事在这里不存在。
- **写后不必重扫索引**：一次连续替换会让编辑点之后的所有 span 平移同一个 `delta`，内存里平移即可（重扫是 24ms，留给外部改动）。外部改动仍然走 `isStale()`（Phase 2）。

## 架构

```
定位：页元素 [start, end)（已有的偏移索引）
      → 在该切片内用同一套 depth 状态机再深一层，找到字段值的确切字节区间 [v0, v1)
      → 只替换 [v0, v1)，其余字节原样
写入：copy → 拼接 → 写临时文件 → rename（与 config.ts 的 writeConfig 同一套原子写）
校验：写前用 parseBookMeta / checkOcrPage 那一套规则拒绝坏值；写后回读该页再核一次
失效：平移缓存 span + 广播 book:changed（界面自己重读，页码与滚动位置不动）
```

几条硬要求：

- **字段区间必须由 depth 状态机给出，不能用"文本搜索第 N 个 `block_content`"**。块的**内容里**完全可能恰好出现 `"block_content"` 这样的字面量（HTML 片段、代码示例），文本搜索会改到别的字节。`offsetIndex.ts` 里的状态机已经知道"是否在字符串里"，深一层就能安全地只认键。这条要有刁钻输入的测试。
- **乐观并发**：保存前把"我读到的那个页元素字节"与磁盘上同一区间再比一次（按偏移读，0.1ms），不一致就拒绝并提示"文件已被外部修改"。比 `mtime` 精确，且不需要额外记账。
- **不留未保存状态**（A5 收窄后的样子）：每次保存立即落盘，写失败就报错、原文件不动。
- **撤销**：内存里留上一版字段字节（几十字节）＋ 位置，`Ctrl+Z` 或"撤销这次修改"即可；跨页的多步撤销栈同样只存差异。

## 交互（高效与易用的具体含义）

1. **就地改，不换面板**：翻页模式下，块卡片 hover 出现铅笔（或双击卡片）→ 卡片**原地**变成编辑态，预填原始 `block_content`。**显示源码、不渲染**：你编辑的就是文件里那段字符（渲染再转回源码是有损的，而且会让人以为改的是"显示效果"）。
2. **保存靠键盘**：`Ctrl+Enter` 保存 / `Esc` 取消；**失焦不保存**——点别处就悄悄写盘是最容易被骂的行为。
3. **保存后**：卡片立刻显示新文本，加一句"已写入 ocr.json"与一个"撤销"。
4. **Markdown 视图同理**：编辑这一页的 `markdown.text`；编辑器标题**必须**写明正在编辑什么——`块 3 的内容` / `这一页的 Markdown`。
5. **两个视图不一致是设计，不是 bug**（A10）：`markdown.text` 与 `parsing_res_list` 是同一页的两份独立读法，互不派生。在块视图改一句话，Markdown 视图**不会**跟着变。所以编辑器必须在两处都说清"你在改哪一份"，并且**不提供**"同步到另一边"（那需要复刻 PaddleOCR 的拼接规则）。
6. **连滚模式**：块卡片上给一个"到翻页模式编辑这一页"的按钮，点了切到翻页模式并定位到同一页。

## 编辑器技术选型

**先不要 Monaco。** 要改的是"一段文字"，Monaco 是为"一个文件"设计的：约 2MB bundle + worker（还得在 `app://` 下再配一次 worker，pdf.js 已经踩过一遍）。分两步：

- **块**：就地 `<textarea>`（自动增高、用阅读字号），几千字节的内容足够。这是频率最高的编辑，越快越好。
- **Markdown（整页）**：也是 textarea，改用等宽字体。页级 Markdown 3–13KB，用 textarea 完全够；**如果**将来觉得不够（长文、查找、行号），再只在这一个场景**懒加载** Monaco——它是加分项，不是前提。

表格块的内容是 HTML：编辑的就是 HTML 源码（第 4 条原则）。将来若要"表格专用编辑"，那是**另加一个视图**，不是替换源码编辑器。

## 明确不做

| 不做 | 为什么 |
|---|---|
| 改 `block_bbox` / 移动块 / 增删块 | 用户的边界：只修正内容。坐标是 OCR 的产物 |
| 改 `block_label` | 颜色与筛选都依赖它，改它等于改结构 |
| 从块重建 Markdown，或反向 | A10 已否：要复刻 PaddleOCR 的排版规则 |
| 整页 JSON 编辑（上一版方案） | 把坐标与结构暴露成可编辑文本，收益是"开发者能改一切"，而我们要的是"读者能改文字" |
| 多窗口并发编辑 | 单实例；外部改动靠乐观并发拦下 |

## 验收

- [ ] 改一个块的一段文字 → 保存 → 卡片与新读回的一致；`ocr.json` **其余字节逐字节不变**（比对前缀/后缀哈希）；页数与别的页的内容都不变。
- [ ] 改这一页的 Markdown → Blocks 视图**照旧**（A10），并且界面明确说了这件事。
- [ ] 保存前文件被外部改过 → 保存被拒并提示，原文件未被动。
- [ ] 撤销 → 文件回到改动前（哈希一致）。
- [ ] 连滚模式下点"去编辑这一页" → 切到翻页模式并停在同一页。

## 风险

| 风险 | 注意什么 |
|---|---|
| 字段定位错一个字节 → 文件损坏 | 只用 depth 状态机定位；写前写后都校验；写用原子 rename；原文件在 rename 之前始终完好 |
| 用户以为改块会改 Markdown | 编辑器标题写明对象；两处都说清 A10 这条设计 |
| 每改一次就写 8MB | 实测 7.5ms/次，可接受；若连续改很多块觉得不顺，再考虑"攒批保存"（但那会重新引入未保存状态） |
| 与外部编辑打架 | 乐观并发（按偏移重读并比对），不做锁 |
