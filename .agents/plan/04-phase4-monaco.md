# Phase 4 —— Monaco 按页编辑（独立立项，暂不动工）

**状态**：🅿️ 搁置。这一阶段**重新引入"写"**，所以它不进 Phase 1–3 的只读基线，要单独拍板、单独验收。

**目标**：在应用里能够按页改元数据，并且**当场校验**；改的是用户自己的 JSON 文件，不是数据库。

---

## 关键设计（读与写对称，都用同一份偏移索引）

```
读：扫一遍建偏移索引 → 取 `layoutParsingResults[n]` 的 [start, end) → 交给 Monaco 显示
写：Monaco 里的内容重新序列化 → 替换文件里 [start, end) 这一段字节 → 其余字节一个不动
                                    → 失效索引 → watch 回读 → 校验
```

- **不把 20MB 文档塞进编辑器**：只喂一页（20–70KB）。这是 Phase 0 那份实测的直接红利（`baseline.md`）。
- **字节区间拼接**：写回时只替换该页那一段，文件其余部分（用户的注释以外的一切、缩进、CRLF、别的页）**逐字节不变**——比"整文件重写"安全得多，`git diff` 也只有一页。
- **写入前必须过校验**：用 Phase 2 那个 `validateBook` 的同一套消息（同一份规则在编辑器里变成 diagnostics，不做第二套）。
- **写后失效索引**：文件长度变了，后面的偏移全部作废 → 丢掉缓存、下次读时重扫（36ms 量级，可接受）。
- **写是原子的**：先写临时文件再 `rename`（`src/main/config/config.ts` 里的 `writeConfig` 就是这个写法，照抄）。

## 任务（粗，动工前细化）

- [ ] 接 Monaco：`monaco-editor` + Vite 打包（注意 worker 的加载方式；Electron 下不能用 CDN）。
- [ ] 编辑器面板：按页打开、显示 `JSON` 语法高亮、折叠。
- [ ] JSON Schema：从 `BookMeta` / 页 JSON 的形状生成（`ajv` 或手写轻量校验），映射成 Monaco markers。
- [ ] 保存路径：`book:writePage`（新通道）+ 原子写 + 索引失效 + watch 回读。
- [ ] 冲突处理：如果文件在编辑器打开期间被外部改了（`mtime` 变了），保存前要提示"文件已变化"，不覆盖。
- [ ] 只有"页 JSON"与 `meta.json` 可编辑；PDF、封面、`toc.json` 仍建议用户在外部编辑器里改（或后面再加）。

## 验收

- [ ] 改坏一个字段（比如把 `block_bbox` 写成 3 个数）→ 编辑器里当场标红、**拒绝保存**。
- [ ] 保存一个合法修改 → 磁盘上该页那一段被替换，**文件其余部分逐字节不变**（用 sha256 分段比对验）。
- [ ] 保存后两个视图（Markdown / Blocks）立刻一致。
- [ ] 编辑器打开期间外部改了文件 → 保存时被拦下并提示。

## 风险

| 风险 | 注意什么 |
|---|---|
| Monaco 的 worker 在 `app://` 协议下加载 | 先做个最小验证（Vite 的 `?worker` 与 `base` 配置），别等接完了才发现 |
| 一页的 JSON 重新序列化会改掉用户那一段的缩进 | 可接受，但要在文档里说明"只有你改的那一页会被重排" |
| 写坏文件 | 原子写 + 写前校验 + 写后回读校验；**永不**整文件重写 |
| 与 Phase 2 的 watch 打架 | 自己写完之后要能识别"这是我改的"（记 `mtime` + 短暂忽略窗口） |
