# tests/unit/library

## 这个目录做什么

书库业务层的集成测试：台账、读一本书、登记一个文件夹。这里跑的是**接近真实使用**的链路，只是文件都在临时目录里。

## 关键文件

| 文件 | 说明 |
|---|---|
| `library.test.ts` | 列表（空库、正常一本、**文件夹被移走后仍列出来并带上原因**）；`open()`（已有 `meta.json` 时**一个字节都不写**、重复登记、**无 `meta.json` 时创建它并把页数取自 OCR 数组**、不是书时说明缺什么、是文件/不存在时拒绝、OCR 没有页时拒绝）；读页与越界返回 `null`；**`readPdfRange` 是闭区间**（差一字节就会让每一页渲染坏掉）；`toc.json` 缺失/损坏的两种行为；进度写入与越界拒绝；**`remove()` 只删台账条目、磁盘上的文件全在**；**书可以放在默认位置之外**（A11）；**外部改动**（改 `meta.json` 的标题、改 `ocr.json` 的正文、`refresh()` 后重读、书在打开状态下变坏）各自在下次读取就能看到 |
| `book.test.ts` | `openBook()`：1-based 页号、1 页对应数组下标 0、小 chunk 跨块也不变；越界/非整数页号报错；**页数以 OCR 文件为准而不是 meta**；PDF 缺失仍可读；meta 缺失/不是 JSON/缺 uid 均报错；**`ocrFile` 跳出文件夹被拒**；封面名探测与 `toc.json` 读取 |
| `watch.test.ts` | 书文件夹 watcher：变更带 `uid` 上报、编辑器连写多次只报一次、从列表移除后不再报、watch 挂不上时降级为轮询（`degraded`/`unwatched`）、`dispose()` 之后彻底安静、只动了封面这类未跟踪文件也会说"这儿变了" |
| `ledger.test.ts` | 台账：新建为空、根内相对路径/根外绝对路径、**整库改名后相对路径仍能解析**、同一本不重复登记、**`remove()` 只删条目而文件夹还在**、手改坏的台账能保住好条目并给出 issues、非 JSON 不崩、跨实例持久化与原子写 |

## 对外接口

无。

## 依赖方向

引用 `src/main/library/**`、`src/main/progress.ts` 与 `tests/helpers/bookFolder.ts`。

这一组是这一阶段最重要的护栏，因为书库现在完全建立在**用户磁盘上的普通文件**之上：任何一个"应用悄悄动了用户的文件"的回归，都应该在这里被抓住。
