# src/renderer/components/layout

## 这个目录做什么

整窗级别的框架组件：顶栏、更新提示条，以及面板之间的拖拽分隔条。它们不属于某一个页面，而是首页与阅读器共用的外壳。

**窗口按钮由本目录自己画，不用 Windows 的 `titleBarOverlay`。** 后者会自己画一条底与三个按钮，但那条底的**颜色与页头是两套**（暗色下露出一块色差），而且它只肯给关闭按钮上色——另外两个怎么调都是灰的，两个毛病都没有 API 可改。自绘之后：三者同在页头的底上，高亮**整条顶满**（从顶栏上沿到下沿，而不是浮在中间的小色块），缝隙问题也不存在了。

**红色是刻意留的**：关闭悬停用 `#E81123`（Windows 自己的那个红，两个主题下都一样），而不是 `--destructive`——后者在暗色主题里是一层发白的粉，压不住"这个按钮会关掉窗口"的语义。这个颜色写死在组件里是有意的，注释里写了原因。

代价是两件事要自己保证：按钮必须标 `no-drag`（否则点击被拖动区吞掉），以及最大化/还原的图标要订阅 `window:maximized`——双击拖动区、`Win+↑`、拖到屏幕边缘都会改变窗口状态，不只是点我们的按钮。

## 关键文件

| 文件 | 说明 |
|---|---|
| `AppHeader.tsx` | 首页与阅读器共用的顶栏：面包屑（阅读器）、首页的 Upload 入口、**两栏都有的 Bolt 设置入口**（阅读字号是读的时候才想改的，所以它不能只在首页）、有未保存修改时书名旁的琥珀色圆点。**同时是整窗的拖动区**，右端放着窗口按钮 |
| `WindowControls.tsx` | 自绘的最小化 / 最大化-还原 / 关闭按钮，走 `window:*` IPC |
| `UpdateBanner.tsx` | 新版本就绪时的非模态提示条 |
| `PaneSash.tsx` | 面板之间的拖拽分隔条：**布局宽度 0**，只在悬浮/拖动时浮出一层可见带（理由见文件头注释与 `DESIGN.md` 第 9 节） |

## 对外接口

`AppHeader`、`WindowControls`、`UpdateBanner`、`PaneSash`。

## 依赖方向

被 `App.tsx` 引用。依赖 `window.api.window`（窗口按钮）与 `lucide-react`。**不依赖 `electron`**。
